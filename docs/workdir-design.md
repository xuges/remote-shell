# WorkDir 设计

状态：设计稿，尚未实现。

WorkDir 表示远端命令开始执行时的工作目录。采用“连接默认目录 + 单次命令覆盖”的模型，保留当前每次调用创建独立 SSH 命令会话的方式。

## 命令行接口

```sh
# 设置当前后台服务的默认远端工作目录。
start-remote-shell -host=server -user=root -workdir=/srv/app

remote-shell pwd                          # /srv/app
remote-shell ls -la                       # 列出 /srv/app
remote-shell -workdir=/var/log ls -lh      # 单次覆盖
remote-shell -workdir=logs pwd            # /srv/app/logs
remote-shell -workdir=logs -c 'ls *.log | head'
remote-shell-info                        # 增加“工作目录：/srv/app”
```

客户端选项必须位于远端命令之前，遇到第一个命令参数就停止解析；`--` 显式结束本地选项。`remote-shell ls -workdir=x` 中的 `-workdir=x` 必须传给远端 ls。保留现有 `-c` 模式，其表达式不再解析为本地选项。

## 目录选择与生命周期

优先级：单次请求的 WorkDir > 服务默认 WorkDir > 启动时探测到的 SSH 初始目录。

启动时通过 SSH 探测初始目录和远端 HOME。未设置 `-workdir` 时，将初始目录固定为服务默认目录；通常是远端用户主目录，但以实际探测结果为准。默认目录在服务运行期间保持不变，重启时重新确定。

启动参数中的相对目录以 SSH 初始目录为基准；单次请求中的相对目录以服务默认目录为基准。两者都由远端 Shell 解析、验证，不能使用本机 `filepath.Abs` 或 `filepath.Clean` 处理。

路径规则：

| 输入 | 含义 |
| --- | --- |
| `/srv/app` | 远端绝对目录 |
| `logs`、`../shared` | 相对于上述基准目录 |
| `~`、`~/app` | 远端 HOME 或其子目录 |
| `$HOME/app`、`*.log` | 字面路径，不展开变量或通配符 |
| `~other/app` | 第一版拒绝，提示使用绝对路径 |
| 显式空字符串、含 NUL 的字符串 | 拒绝 |

客户端只传递原始路径；`~` 和 `~/` 由服务根据启动时探测的远端 HOME 展开，不执行任意 Shell 表达式。若远端 HOME 不可用，则这两种写法报错。

本机 Shell 会提前展开未引用的 `~`、`$HOME`，因此访问远端主目录应写成 `-workdir='~/app'`。

使用远端 `cd -P` 和 `pwd -P` 获得物理目录语义，启动后保存解析完符号链接的绝对路径；单次执行也使用物理目录语义。路径包含符号链接和 `..` 时，必须保持远端实际解析顺序，不能在本机先做字符串化简。

## 执行语义

每次命令执行前在同一个远端 Shell 中进入选定目录，再执行用户命令。只有进入目录成功才执行命令，避免落到其他目录执行带有写入或删除操作的命令。

绝对路径的包装逻辑示意如下，实际实现须用现有 POSIX 参数引用函数转义路径：

```sh
CDPATH= cd -P '/srv/app' || {
    printf '%s\n' 'remote-shell: 无法进入工作目录' >&2
    exit 125
}
# 此处接原有普通模式引用后的命令，或 -c 的完整表达式。
```

相对路径先进入服务默认目录，再进入目标相对目录，两个步骤都必须检查结果。显式相对路径加上 `./` 前缀，避免以 `-` 开头的路径被 cd 当作选项。清空 CDPATH，避免远端环境把相对路径定位到其他目录或向 stdout 输出目录名称。

目录不存在、目标是普通文件、没有进入权限时：

- 启动默认目录验证失败：启动失败，清理后台服务和 SSH 连接。
- 单次目录验证失败：stderr 输出带 `remote-shell:` 前缀的目录错误，退出码为 125；不执行用户命令，不改变默认目录。
- 启动后目录被删除或权限变化：后续命令同样报目录错误，不自动创建或回退。

125 也可能是用户命令自身的退出码，因此不能仅凭该退出码断言发生了目录错误；目录错误同时带有上述诊断。SSH 传输错误继续使用 255，用户命令的退出码继续原样转发。

目录切换不得读取命令 stdin，不得向命令 stdout 写入额外内容。普通参数引用、二进制数据流、stderr 分离和实时输出保持原有行为。

## 状态与并发

默认 WorkDir 属于当前服务连接；单次 WorkDir 只属于对应请求。并发命令各自在自己的 SSH 通道切换目录，相互不改变目录。

`remote-shell cd /tmp` 只改变该次 Shell 的目录；下一次命令仍从服务默认目录开始。`remote-shell -c 'cd /tmp && ls'` 在同一次调用内正常工作。

第一版不提供运行时修改服务默认目录的接口。这样多个终端使用同一服务时，不会因某个客户端切换目录而改变另一个客户端的执行位置。

`remote-shell-info` 和 JSON 的 `work_dir` 字段显示已配置的默认绝对目录，不表示正在运行的每个命令的实时目录，也不保证该目录此刻仍然存在。SSH 状态探测不应用 WorkDir；工作目录失效与 SSH 连接断开是两个独立状态。

## 代码改动

- `config` 增加 `WorkDir string`，保存启动参数；默认目录解析后存入服务状态。
- `request` 增加 `WorkDir *string`、JSON 名称 `work_dir`，区分未指定与显式空字符串。旧客户端未携带该字段时使用默认目录。
- `connectionInfo` 增加 `WorkDir string`、JSON 名称 `work_dir`。
- 启动探测补充初始目录和 HOME，并单独执行默认目录校验。目录探测使用带标记的 NUL 分隔字段，保留路径中的空格和换行。
- 增加路径解析及命令包装函数，仅在 `exec` 请求中使用；保留底层 SSH 调用用于系统探测和启动校验，避免把 WorkDir 误用于所有 SSH 操作。
- `Start` 和 `Execute` 增加 `-workdir` 参数解析；`Info` 展示默认目录。

现有 `config.Dir` 表示本地 socket、锁和日志所在的运行目录，与远端 WorkDir 分开保留。远端路径不写入本机进程的 `exec.Cmd.Dir`。

## 验证范围

在现有真实 SSH 集成测试中增加：未指定时的实际默认目录、启动指定绝对/相对目录、单次绝对/相对覆盖、远端 HOME 展开、物理路径及符号链接、带空格/引号/换行/美元符号/前导连字符的路径、无效目录和权限错误。

同时验证目录失败时用户命令没有执行、并发覆盖互不影响、单次 cd 不影响后续调用、`-c` 表达式和命令自身参数解析兼容、stdin 不被目录探测消费、stdout 不被 CDPATH 或 pwd 污染、默认目录失效后 SSH 状态仍可查询。
